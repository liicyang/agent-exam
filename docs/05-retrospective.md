# 复盘（工程记录与本人待补部分）

## 本次实现中的关键问题

难点不是调用 API，而是模型提议与真实业务状态的一致性。解决方式是让模型决定动作，让工具约束授权、审核和存储，再由运行时根据证据汇总结果。测试专门模拟了模型直接声称 saved，确认系统仍返回 incomplete。

时间冲突涉及建议和授权两个不同状态：找到可用时段不意味着获准改期。当前先返回 needs_confirmation，用户修改可信输入后才允许保存。

重复执行不能简单重复 INSERT。当前使用稳定 request_id、请求指纹、唯一约束和事务，重复请求返回旧草稿，变更请求拒绝。
