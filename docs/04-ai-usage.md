# AI 辅助内容、个人参与及验证记录

## AI 辅助范围

本项目使用 Codex 辅助完成选题比较、方案设计、Python 代码实现、测试编写和文档整理。具体包括 Agent 决策循环、DeepSeek 接口适配、四个业务工具、SQLite 草稿存储、离线 Mock、合成测试资料及验收脚本。Codex 还协助查阅 DeepSeek 官方接口文档，在本机执行测试、分析失败记录并修正代码。

项目运行时使用的 DeepSeek 与开发阶段的 Codex 承担不同职责：Codex 辅助开发和验证；DeepSeek 在真实运行中根据请求和工具结果选择下一步动作。离线 Mock 仅用于流程测试，其脚本分支不作为真实模型决策效果的证明。

## 个人参与与修改分工

本人提供了任务要求与交付约束，在 AI 给出选题建议后确认开始项目开发；提供 GitHub 仓库和本机环境信息，并完成本地 DeepSeek API 密钥配置，使项目能够进行真实模型验收。

在交付材料整理过程中，本人要求逐项说明验收输入、实际输出及 Trace 的位置，并提出补充 README 代码架构介绍、删除末尾提交说明等修改要求。这些文档修改由本人提出，具体编辑和 GitHub 同步由 Codex 执行。

本项目的个人参与主要体现在任务推进、环境与账号准备、API 配置和文档修改要求上。核心代码、自动化测试及下述问题修复由 AI 辅助生成和执行，不将其表述为本人独立手写或独立完成的调试工作。

## 实际问题与修正

首次真实模型调用中，DeepSeek 向零参数的 `read_material` 工具额外传入了 `material_id`。工具按参数约束拒绝执行，模型再次尝试后结束任务。原始失败记录保存在 [initial-argument-failure.json](../examples/real/initial-argument-failure.json)。

针对这一问题，Codex 修改了提示词，明确前三个工具的参数必须为 `{}`；同时在参数错误反馈中增加 `expected_arguments`，帮助模型依据工具反馈修正调用，并增加对应回归测试。请求身份仍由运行时绑定，没有通过放宽授权或身份约束绕过错误。修改后的八类真实模型验收全部通过。

验证中特别检查：未确认的替代时段不保存；保存失败时数据库无草稿；相同请求执行两次只有一份草稿；占用条件变化后，模型建议从 19:00 调整为 20:00。失败和成功记录均保留，没有用预设日志替代真实模型运行结果。

这些结果对应固定场景的一轮验收，尚未进行多轮模型稳定性评测或多进程并发压测。实际用时和个人学习收获在复盘文档中另行据实记录。
